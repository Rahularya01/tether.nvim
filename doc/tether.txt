1. Overview                                                      *tether.nvim*

tether.nvim is the editor side of terminal coding agents. Claude Code, Gemini
CLI, Codex, and OpenCode keep their own terminal UI. This plugin makes Neovim
visible to them the way the VS Code and JetBrains extensions do: the focused
file, the selection, open buffers, diagnostics, and diffs you accept or
reject.

Requires Neovim 0.11 or newer, on macOS or Linux. The plugin needs
/dev/urandom and Unix sockets.

Run the agent from a |terminal| inside Neovim. New terminals inherit the
environment the agents look for. Claude Code and Codex can also attach from
another terminal with /ide. Gemini CLI finds Neovim by walking its parent
processes, so start it from Neovim's terminal.

2. Setup                                                        *tether-setup*

With lazy.nvim:
>lua
  { "Rahularya01/tether.nvim", lazy = false, opts = {} }
<
With vim.pack:
>lua
  vim.pack.add({ "https://github.com/Rahularya01/tether.nvim" })
<
Calling setup() is optional. The plugin starts on |VimEnter| unless
*g:tether_disable* is set. Pass options to setup() or through *g:tether* :
>lua
  require("tether").setup({
    adapters = { "claude", "gemini", "codex", "opencode", "herdr", "tmux" },
    pick = "always",
    focus = false,
    keymaps = {
      send_file = "<leader>af",
      send_selection = "<leader>ao",
      send_diagnostic = "<leader>ad",
      send_node = "<leader>an",
      focus = "<leader>aj",
    },
    review_keymaps = { accept = "ga", reject = "gr", hunk = "gh" },
    gemini = { trusted = nil },
    tmux = { agents = {} },
  })
<
adapters        Which adapters to start. All six by default.
pick            "always" (default) asks which pane agent gets the text, even
                when there is only one. "auto" asks only when there are
                several.
focus           When true, a send also focuses that Herdr or tmux pane.
keymaps         Set one to false to skip it, or keymaps = false for none.
review_keymaps  Buffer-local maps on a proposal. Set one to false to skip
                it, or review_keymaps = false for none.
gemini.trusted  nil leaves workspace trust to Gemini CLI. true or false
                overrides it.
tmux.agents     Extra process basenames to treat as agents. A list, or a
                map of { basename = "label" }.

3. Commands                                                  *tether-commands*

:TetherStart            Start the adapters
:TetherStop             Stop them and remove discovery files
:TetherStatus           Show ports, sockets, clients, agents, and open reviews
:TetherEnv              Print export lines for a terminal opened earlier
:TetherAccept           Write the proposed edit. See |tether-review|
:TetherAcceptHunk       Write the hunk under the cursor
:TetherReject           Discard the proposed edit
:TetherReviews          Jump to an open review
:TetherFocus            Focus the pane that last received text
:TetherLog              Show recent protocol events
:TetherSendFile         Add the current file to an agent's prompt
:[range]TetherSendSelection
                        Add the lines in [range], or the selection
:[range]TetherSend      With a range, the lines. Without one, the file
:TetherSendDiagnostic   Add the diagnostic under the cursor
:TetherSendNode         Add the function or type around the cursor

The commands from before the rename (:AiSend and the rest) still work.

                                                              *tether-keymaps*
<leader>af      (normal) :TetherSendFile
<leader>ao      (normal, visual) :TetherSendSelection. From normal mode it
                uses the last visual selection.
<leader>ad      (normal) :TetherSendDiagnostic
<leader>an      (normal) :TetherSendNode
<leader>aj      (normal) :TetherFocus
ga              (proposal buffer) :TetherAccept
gh              (proposal buffer) :TetherAcceptHunk
gr              (proposal buffer) :TetherReject

4. Sending to an agent                                           *tether-send*

The send commands put a reference such as @lua/tether/init.lua#L10-24 in an
agent's prompt and show a notification saying where it went. Nothing is
submitted. Press Enter in the agent when the prompt is ready.

The text goes to the first of these that is available:

1. Agents in Herdr or tmux panes. A picker (|vim.ui.select()|) lists them,
   with the agent used last first. When Neovim runs inside Herdr or tmux,
   only agents in the same Herdr workspace or tmux session are listed.
   Outside both, agents whose directory is the current project are listed.
   After the agent used last, the order is: the same tab or window, Claude,
   the same project directory, the focused pane, an idle one.
2. Claude Code over its IDE connection, as an at-mention.
3. OpenCode, appended to its prompt.

Claude gets @path#L10-24. Other agents get path:10-24. A path with spaces is
quoted: @"my file.lua#L3". A buffer with no path on disk sends its text.
Claude Code's at-mention needs a path, so that text goes to a pane agent or
to OpenCode.

5. Reviews                                                     *tether-review*

When Claude Code or Gemini CLI proposes an edit, a tab opens with the file
next to the proposal. The proposal can be edited before accepting.

ga or :TetherAccept writes it. It refuses if the file has unsaved changes,
because accepting would overwrite them. Write or undo them first. The text
reported to the agent is the buffer after the write, so format-on-save is
included. gh or :TetherAcceptHunk writes only the hunk under the cursor and
leaves the review open until the last difference is accepted. gr or
:TetherReject discards what is left, and so does closing the tab. Hunks
already written stay on disk. ga, gh, and gr are buffer-local on the
proposal. :TetherStatus lists a review that is still open, and
:TetherReviews jumps to one.

A second proposal for a file that already has a review waits, and opens
when the current one finishes. When you answer in Claude's terminal
instead, Claude closes the tab.

6. Adapters                                                  *tether-adapters*

Claude Code ~
Writes a lock file in ~/.claude/ide/ and serves a WebSocket MCP server with
openFile, getCurrentSelection, getLatestSelection, getOpenEditors,
getWorkspaceFolders, getDiagnostics, checkDocumentDirty, saveDocument,
openDiff, close_tab, and closeAllDiffTabs. Cursor movement is pushed as
selection_changed.

Gemini CLI ~
Writes gemini-ide-server-<pid>-<port>.json under the temp directory and serves
MCP over HTTP at /mcp. Context is pushed as ide/contextUpdate on the event
stream. openDiff returns at once, and the result is sent later as
ide/diffAccepted or ide/diffRejected.

Codex ~
Serves $CODEX_HOME/ipc/ipc.sock and $TMPDIR/codex-ipc/ipc-<uid>.sock and
answers ide-context. In the TUI, turn this on with /ide. If another editor
already serves a socket, tether.nvim leaves it alone and takes it over after
that editor exits.

OpenCode ~
Reads server.json in OpenCode's state directory and uses that server to
append to the prompt. A server started later is found within 2 seconds.

Herdr ~
Lists agents with `herdr agent list` and types into the chosen pane with
`herdr pane send-text`. Neovim's workspace comes from $HERDR_WORKSPACE_ID.

tmux ~
Lists panes with `tmux list-panes -a` and counts a pane as an agent when a
known agent CLI runs in it. The command names are the ones Herdr detects:
pi, claude, codex, gemini, cursor (cursor-agent), devin, agy (Antigravity
CLI), cline, omp, mastracode, opencode, copilot, kimi, kiro, droid, amp,
grok, hermes, kilo, qodercli, qwen, letta, maki, and muse, plus aider,
crush, and goose, plus any names in |tether-setup|'s tmux.agents. Agents
in an editor's own terminal are not counted.
Types into the chosen pane with `tmux send-keys -l`. Neovim's session
comes from $TMUX_PANE.

Listeners bind to 127.0.0.1. Claude Code and Gemini CLI must present the
per-session token from the discovery file. Discovery files are mode 0600.

7. Health                                                      *tether-health*
>
  :checkhealth tether
<
Reports whether tether.nvim is running, lists an open review, and warns
about Claude lock files and Gemini discovery files left by a Neovim that
exited without deleting them.

The last Herdr or tmux pane you sent text to is stored in
stdpath("state")/tether-last.json and offered first next time.

*TetherClient* and *TetherReview* are |User| autocommands.
>
  vim.api.nvim_create_autocmd("User", {
    pattern = "TetherClient",
    callback = function(args)
      -- args.data = { adapter = "claude", clients = 1 }
    end,
  })
  vim.api.nvim_create_autocmd("User", {
    pattern = "TetherReview",
    callback = function(args)
      -- args.data = { action = "open", path = "/path/to/file" }
      -- action is "open", "hunk", "accept", or "reject"
    end,
  })
<
Gemini CLI's context update has no diagnostics field, and Codex's socket
only answers ide-context. Send a diagnostic with |:TetherSendDiagnostic|.
An unrecognized Codex method is recorded in |:TetherLog|.
